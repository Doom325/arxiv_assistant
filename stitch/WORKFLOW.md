# Stitch Workflow

Google Stitch generates the design mocks. This file is the process contract between you and the agents.

---

## Directory Structure

Each page/component gets its own directory:

```
stitch/
├── WORKFLOW.md              — this file
├── <page-name>/
│   ├── STITCH_PROMPT.md     — generated by design-reviewer (pre-stitch mode)
│   ├── FUNCTIONAL_REQUIREMENTS.md — generated by design-reviewer (pre-stitch mode)
│   ├── screen.png           — YOU save this from Stitch
│   ├── code.html            — YOU save this from Stitch
│   └── SPEC.md              — generated by design-reviewer (post-stitch mode)
```

The files you produce (screen.png, code.html) are the handoff point between you and the agents. Nothing builds until both exist and SPEC.md has been written and approved.

---

## The Loop (per page/component)

```
1. Run design-reviewer (pre-stitch)
   → reads current code
   → writes STITCH_PROMPT.md + FUNCTIONAL_REQUIREMENTS.md
   → you review both before opening Stitch

2. You open stitch.withgoogle.com
   → paste STITCH_PROMPT.md content
   → iterate visually until satisfied
   → export screen.png and code.html to stitch/<page>/

3. Run design-reviewer (post-stitch)
   → reads screen.png + code.html + FUNCTIONAL_REQUIREMENTS.md
   → writes SPEC.md
   → escalates any coverage gaps

4. You review SPEC.md
   → if gaps: either go back to Stitch (step 2) or resolve escalation
   → if satisfied: approve ("looks good, proceed")

5. After 2+ SPECs approved: run ui-architect
   → reads all SPECs, writes OVERHAUL_PLAN.md

6. Build loop begins (ui-builder + behavior-validator)
```

## What Makes a Good Stitch Session

Before submitting a Stitch output to design-reviewer, check:

- [ ] Every capability listed in `STITCH_PROMPT.md` has a visible UI element somewhere in the design
- [ ] At least two surface levels are visibly distinct (e.g., cards sit on a different bg than the page)
- [ ] The primary accent (indigo) appears on at least one actionable element
- [ ] The design includes at least one non-trivial state beyond the default (hover, selected, loading, empty)
- [ ] Typography clearly differentiates headlines from body text

If any are missing, iterate in Stitch before saving. design-reviewer will flag them as gaps anyway, but catching them here saves a round trip.
